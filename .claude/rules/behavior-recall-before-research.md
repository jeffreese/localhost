# Recall Before Research

Before investigating runtime behavior, API capabilities, or configuration through SSH probing, web fetching, or trial-and-error — search recall first.

## Triggers

Search recall when:
- **Prior findings** — "has this been figured out before?" API behavior, runtime probes, config discoveries, error resolutions, compatibility answers
- **Project referenced** — a project or dependency that may have documented decisions or constraints
- **Before recommending** — about to suggest an approach, library, or tool choice
- **Topic shift** — conversation moves to a domain where prior sessions may have relevant context
- **Recurring pattern** — a problem that feels familiar or similar to something encountered before
- **Before pivoting** — about to change implementation approach because something didn't work as expected

## What this prevents

The failure mode is going straight to investigation when the answer is already in recall from a prior session. A 2-second search saves a 5-minute probe and surfaces constraints or gotchas the prior session discovered.

## What this does NOT mean

Don't search recall for things that are obviously new — first encounter with a codebase, novel error, greenfield design. The trigger is "this feels like it might have been figured out before."
